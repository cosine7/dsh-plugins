# 飞书通道

让 DeepSeek Harness 桌面版 Session 与手机飞书机器人双向通信：主动消息与卡片按钮实时唤醒订阅 Session，Session 可发送文字、图片、确认卡片并更新处理结果，插件运行异常可主动通知手机。

当前适配桌面版 DSH `0.2.2-rc.3`，Node.js 最低要求 `24.9.0`。

## 接入

构建仓库后，通过 DSH 桌面 CLI 安装本地 `packages/feishu` 目录，方法见[仓库说明](../../README.md)。重启 DSH，在目标 Session 中让 Agent 读取 `dsh-feishu` skill 并配置飞书。

1. 选择创建新应用或接入现有应用。Agent 展示二维码和配置链接，用户扫码确认；凭据直接写入 DSH 凭据服务。
2. Agent 查询配置结果并运行 `feishu_check`。确认机器人已启用，拥有 `im:message:send_as_bot`、`im:message.p2p_msg:readonly`、`im:message.reactions:write_only`、`im:resource`（图片上传）权限，事件 `im.message.receive_v1` 和回调 `card.action.trigger` 均使用长连接。按控制台提示发布应用并设置可用范围；配置变更后重新连接。已有应用缺少权限时，用 update 扫码配置补充授权，无需重建机器人。
3. 确认唯一授权用户 open_id，由目标 Session 主动调用 `feishu_subscribe`。从飞书发送文字并点击测试卡片，核对接收记录。

扫码配置不阻塞 Agent 等待用户；未完成流程在重启后需要重开。已有应用不必重新创建，CLI 与本插件可使用同一应用，但不会自动共享本地凭据；不要同时运行同一应用的其他事件消费者，以免事件分流。

## 通道与卡片

每个机器人一个通道，最多一个订阅 Session。主动文字和按钮点击都交给当前订阅者，转交后旧卡片的点击也交给新 Session，并附完整上下文。没有订阅者仍保持长连接、记录授权用户的消息，历史记录供所有 Session 查看，后续订阅不自动补投。

订阅或转交仍需提供最新 revision；重复订阅/转交给当前 Session 直接返回现状，不增加版本。任务中心默认不操作飞书，只有显式选择通道才联动；联动失败不阻塞任务，执行 Session 可查询状态后独立处理。

普通文字回复通过 Markdown 富文本发送，支持标题、加粗、列表、链接、代码块和飞书支持的表格等格式。长消息按平台大小限制拆分，代码块独立组织；最终样式由飞书客户端渲染，不能视为完整网页 Markdown。

通过 `feishu_send_image` 指定本地图片绝对路径，由 SDK 完成上传和发送，不需要 CLI。支持常见图片格式，文件非空且不超过10 MiB，飞书负责最终格式与分辨率校验；配文通过文字工具另发。发送记录保存路径、SHA-256 指纹和 image_key，不保存图片本体。上传或提交前失败记录为 failed；消息提交结果不确定记录为 uncertain，核对手机后再处理，避免重复发送。

## 查询与主动领取

`feishu_events` 是只读记录查询，不消费消息，也不会取消自动投递。当前执行轮需要提前处理手机回复时，使用 `feishu_claim`：指定通道，可按事件 ID 领取，省略 ID 则领取最早一条 pending。只有通道当前的活动根 Session 能领取，返回 claimed=true 后再处理正文。

领取与自动投递互斥。领取先写入磁盘，成功后标记 claimed，并保存领取会话、时间和执行轮次；该事件不会再自动唤醒另一轮。自动投递已占用或交付的事件不可再领取，重复领取不返回正文。unassigned 历史不因领取而补投。文字的处理表情关联领取它的当前轮，结束后按实际执行状态更新。

claimed 表示处理责任已交给当前轮，不代表业务成功；若进程在领取后退出或工具结果丢失，不自动重新排队。先查询记录并核对实际操作，避免重复执行。没有待处理事件时结束当前轮等待自动唤醒，不通过历史查询或外部轮询构建第二条处理路径。

## 异常主动通知

插件可直接向授权用户发送运行异常，不依赖 Session 订阅、不唤醒 Agent。任务异常默认通知所有已启用通道，飞书联动及本通道故障只通知关联通道。覆盖调度/会话准备、投递异常、飞书转交失败、机器人发送异常、长连接报错和卡片更新失败，不代替 Agent 判断业务成功与否。

通过 `feishu_alerts` 查看通知的 pending、sending、sent、uncertain 状态。同一故障去重，连接报错每通道每小时最多一条；保留最近200条已发送通知及待处理记录，总上限2000条。通知失败不会递归告警。明确未提交的失败等待恢复后重试；提交结果不确定或进程在提交期间退出时不自动重发。DSH退出、没有可用通道、存储初始化失败或飞书不可用时无法保证手机即时收到。新功能不批量回放旧历史故障。

## 处理状态

收到授权用户文字并落盘后，在原消息添加 `OK` 表情，表示已记录；没有订阅者时也只表示记录成功。对应消息被 Agent 接手后改为 `Typing`，该处理轮次完成后移除；异常结束显示 `CrossMark`。表情不表示业务成功，任务执行结果以 Agent 回复为准。表情失败不阻塞投递；重启后把上次仍在处理的状态标为中断。

发送确认卡片时，Agent 指定按钮和有效截止时间；不设置统一业务超时。截止时间不能超过平台14天的消息更新窗口。点击先持久化并移除按钮，显示已收到，最终结果由 Agent 写回。授权用户以外的操作被忽略，同一卡片只接受一次选择。

插件只发送消息和投递事件，绝不下单。确认可能延迟数小时，Agent 必须根据收到时的情况重新判断。会话忙碌时等待空闲；未加载的历史 Session 不自动恢复。归档/停止 Session 取消订阅，正常退出 DSH 保留订阅，重启并加载该 Session 后继续处理队列。

任务中心可以为任务保存通道关联，在创建替代会话、新建会话或转交任务时，通过插件间接口转交订阅。归档时保留可校验的原订阅记录，供该任务接续；用户主动取消或更换订阅后，旧任务不能覆盖它。历史 unassigned 事件不自动补投，归档会话不会被飞书消息恢复运行。

## 存储与运行

应用 ID 和 secret 由 DSH `credentials` 服务管理，插件只保存引用。默认宿主凭据文件为 `$DSH_HOME/.credentials.yaml`；这是宿主的文件凭据机制，不代表 Windows 凭据保险箱加密。

DSH `0.2.1-rc.3` 使用带 `version: 1`、`refs` 与 `records` 分节的凭据格式；宿主启动时自动迁移可识别的旧扁平格式，插件仍通过凭据服务读写，不自行迁移或要求重新扫码。

其他数据保存在 `$DSH_HOME/storages/cosine-feishu/`，默认位于用户的 `.dsh` 目录：通道、订阅、事件、卡片、发送记录及扫码图片。与源码目录无关，不会写入交易项目。扫码链接/图片属于临时授权材料，不应公开分享该目录。

DSH 加载插件后自动建立连接，断线由官方 Node SDK 自动重连；终止性配置错误需修复后调用 `feishu_reconnect`。插件随 DSH 启动，不负责让 Windows 自动启动 DSH；退出应用、休眠和断网期间无法保证在线。飞书不保证离线事件永久重放。

事件先落盘再投递，重复文字与重复按钮点击会去重。发送/投递中途崩溃或持久化无法确认时记录为 uncertain，供人工核对，不自动重复投递。delivered 只代表会话已接收，不代表业务执行成功。
