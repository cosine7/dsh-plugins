# 使用本任务中心

本插件工具以 task_center_ 开头。只管理本插件创建的任务，不读取、修改或替代官方 schedule_* 任务。

## 基本工作流

1. 理解任务内容与时间规则。明确时区、日期、间隔起点、结束时间和午间等排除窗口。仅在影响结果的歧义存在时追问；不要默认“工作日”包含交易日历。
2. 将要求转为下列规则之一。复杂时间先调用 task_center_preview，检查接下来的 UTC 与本地时间是否符合用户意思。
3. 用 task_center_create 创建；`target_mode=session`（默认）复用 target_session_id，省略 ID 为当前会话；`target_mode=new` 每次触发新建，不能同时指定 ID。`cwd` 保存新建或替代会话的绝对目录，省略从源会话获取。prompt 必须自包含。返回规则、任务 ID、目标模式和触发时间。工具报错不代表创建成功。
   创建者通过 `session_title` 指定新会话标题（1–200 字符单行），省略使用任务名称；日期、用途等由创建者自行组织。此标题只用于新建或替代会话，不改已有目标的名称；update 可修改未来会话的 session_title。无需伪造 user 来源触发自动起名，也无需为标题调用模型。
4. 修改、删除、转交前调用 task_center_list，使用精确 id 和最新 revision。发生 revision 冲突就重新读取，不覆盖别人刚做的修改。
5. 用户说“转到这里/不要在 B 里跑”时，调用 task_center_transfer，省略 target_session_id 即当前会话；不是复制任务。转交其他会话需先 task_center_sessions 获取有效 ID。
6. 可通过 update 的 target_mode=new 改为每次新建，改回指定会话使用 transfer。不要自行决定哪些日期共用会话；业务编排由调用者决定，插件只执行给定规则。
7. 任务与飞书独立。create 的 feishu_channel_ids 省略或空数组均不关联；显式选择源会话拥有的通道后，才在新建/替代会话时尝试转交。update 的 changes.feishu_channel_ids 省略保持原设置、空数组解除关联、非空数组选择调用会话当前拥有的通道，只配置未来行为，不立即转交。
8. transfer 默认只转任务并清除原任务的飞书关联，不改变飞书订阅；需要同时转交通道时显式提供 feishu_channel_ids，选择任务原目标当前拥有的通道（new 模式为调用会话）。也可由飞书插件单独执行转交。若联动已经成功，无需再调用 feishu_transfer。
9. feishu_handoff 的 succeeded/failed 单独描述联动结果；failed 不等于任务失败。任务照常投递，消息会附失败原因；核对 feishu_status 后按用户意图处理，不因飞书失败重新创建/重复投递任务，不绕过订阅冲突保护。task_center_history 的 delivered 仍只代表任务已交给会话，不代表飞书已转交或业务已完成。

安装并启用飞书插件后，任务调度/准备、投递不确定与联动失败也会直接通知授权用户，不需要 Session 订阅，不会为通知唤醒 Agent。普通任务异常通知所有已启用通道，联动失败只通知关联通道；通知状态通过 feishu_alerts 查看。飞书不可用或通知提交结果不确定时不能声称用户已收到；通知成功也不代表任务已恢复或业务成功。

## 时间规则

- 一次性：`{"kind":"once","at":"2026-12-01T15:00:00+08:00"}`。日期仅示例，创建时必须在未来。
- 固定间隔：`{"kind":"interval","every_minutes":20}`。默认 20 分钟后第一次；明确起点时加含 UTC 偏移的 `anchor`。始终以 anchor 对齐，不随处理耗时漂移。
- 日历：`{"kind":"cron","timezone":"Asia/Shanghai","expression":"31 9 * * 1-5"}`，每周一至周五 09:31。
- 月末：`{"kind":"cron","timezone":"Asia/Shanghai","expression":"0 20 L * *"}`，每月最后一天 20:00。
- 多窗口间隔：

```json
{
  "kind": "windows",
  "timezone": "Asia/Shanghai",
  "weekdays": [1, 2, 3, 4, 5],
  "windows": [
    { "start": "09:31", "end": "11:30", "every_minutes": 20 },
    { "start": "13:01", "end": "15:00", "every_minutes": 20 }
  ],
  "exclude_dates": []
}
```

每个窗口独立从 start 对齐；上午 09:31、09:51、10:11……11:11；下午 13:01、13:21……14:41。end 是包含的边界，不额外补一个 end 触发。重叠窗口相同时间合并为一次。weekdays=1 周一至7 周日。

windows 可加 start_date / end_date（包含边界）与 exclude_dates，格式 YYYY-MM-DD。跨午夜需拆分并正确调整星期。无交易所日历，不可声称会自动跳过休市日。

cron 使用五字段：分钟 小时 日 月 星期，星期 0/7=周日；不支持 H 随机规则，禁止同时限制日和星期以免歧义。`*/20` 分钟表示整点的 00、20、40，不表示从09:31起每20分钟；后者必须用 windows。

最小间隔 1 分钟。时区必填，不能用机器本地时区猜测。windows 在夏令时跳过不存在的墙上时间，重复时间仅取较早一次；cron 由 cron-parser 的时区规则计算，边界用 preview 验证。

## 生命周期与投递

- DSH 停止就不执行；不会启动系统服务或操作系统定时器。
- 桌面版关闭窗口仅隐藏到托盘，任务仍可执行；从托盘退出应用才停止。归档会话不取消任务，要停止未来触发必须显式暂停或删除任务。
- 指定目标未加载时由宿主恢复；归档或已不存在则创建替代会话，更新当前目标并转交关联飞书通道。替代提示包含原 Session ID 和原因；归档历史可只读查阅，不解除归档或唤醒原会话。存储故障与占用错误不会被当成删除。
- 会话忙时等待空闲。逾期循环任务合并到最近一次触发，不逐次补跑；一次性逾期任务在会话准备且空闲后投递。因此恢复后可能收到一条旧时间的提醒，任务指令可要求先检查当前时间或有效性。
- 目标转交前尚未投递的任务使用新目标。已经投递的消息留在原会话，不撤销、不搬迁、不重复发给新会话。
- enabled=false 暂停；恢复 enabled=true 从当前时间重新计算下一次。已完成的一次性任务必须改未来规则才能恢复。
- task_center_history 的 delivered 只代表消息已投递并完成持久化屏障，不代表模型执行完毕或业务成功。
- 进程在投递期间崩溃时可能出现不确定结果，插件暂停该任务以避免自动重复。先检查目标会话及 Delivery ID，确认后恢复。不要承诺严格 exactly-once 或自动重试业务副作用。

## 范围

可以安排任何文本任务，不局限于股票。条件监控（股价、网页变化等）需要安排定期检查并在 prompt 中描述条件，不能把条件假装成纯时间触发规则。第一版不执行自定义调度脚本，没有额外 Web 管理面板；通过上述工具与聊天管理。

## once / interval 的显示时区

这两类规则现在支持可选 timezone（推荐 Asia/Shanghai 等 IANA 名称，也接受 UTC+08:00）。显式 timezone 仅影响 local 展示，不改变 at/anchor 指定的绝对触发时刻。省略时保留原始 at/anchor 的数字偏移；未提供 anchor 的 interval 保存创建时的宿主时区。原有任务缺少 timezone 时，local 按当前宿主时区展示，不修改任务时间。固定数字偏移不代表地区夏令时规则；需要随夏令时显示时显式使用 IANA 时区。
